# 🤖 دستیار کدنویسی تلگرام

ربات دستیار کدنویسی با پنل ادمین - اجرا روی Cloudflare Workers

## قابلیت‌ها

- 💬 چت هوشمند با Claude AI
- 🐛 دیباگ کد با شماره خط
- 📷 تحلیل اسکرین‌شات خطا
- 🗜️ تحلیل پروژه ZIP
- 🐙 یکپارچه‌سازی GitHub (پوش، برنچ، PR)
- ☁️ اتصال per-user به Cloudflare: مدیریت DNS با تأیید، مشاهدهٔ Zoneها و Workerها
- 🖥️ پنل ادمین وب
- 🧠 اتصال مدل هوش مصنوعی شخصی هر کاربر (پولی یا رایگان) با دکمه‌های شیشه‌ای

## منوی فرمان‌های تلگرام

فهرست فرمان‌ها پس از اولین پیام دریافتی از ربات، خودکار با Telegram Bot API ثبت می‌شود. این فهرست شامل `/start`، `/help`، `/ai`، `/login`، `/logout`، `/project`، `/github`، `/github_off`، `/cloudflare`، `/workspace`، `/workspace_clear`، `/lang`، `/search`، `/debug`، `/clear` و `/new` است. زیرفرمان‌های اتصال و همگام‌سازی مخزن، مثل `repo`، `sync`، `pull` و `push`، از طریق `/project` اجرا می‌شوند.

ثبت فرمان‌ها فقط منوی slash-command تلگرام را به‌روز می‌کند؛ دکمه‌های فعلی ربات در جای خود باقی می‌مانند. برای تحلیل عکس، فایل کد یا ZIP، فایل را مستقیم به گفتگو پیوست کنید.

## اتصال مدل شخصی (Bring Your Own Key)

کاربرانی که به مدل پولی دسترسی ندارند می‌توانند مدل خودشان را وصل کنند:

1. دستور `/ai` یا میان‌بر `/login` را بفرستند (یا دکمه «🔌 اتصال مدل شخصی» را بزنند)
2. **Base URL** سرویس را بفرستند — باید به `/v1` ختم شود (مثلاً `https://api.openai.com/v1`)
3. **API Key** را بفرستند — پیام حاوی کلید بلافاصله از چت پاک می‌شود
4. **نام مدل** را بفرستند — ربات اتصال را تست می‌کند و در صورت موفقیت وصل می‌شود

- دکمه‌های اتصال، وضعیت، تغییر مدل و راهنما به‌صورت منوی شیشه‌ای مرتب زیر پیام نمایش داده می‌شوند؛ دکمه‌های قدیمی کیبورد متنی نیز برای سازگاری پذیرفته می‌شوند.
- هر سرویس سازگار با OpenAI API پشتیبانی می‌شود (OpenAI، Groq، OpenRouter و...)
- مشخصات هر کاربر جداگانه در KV ذخیره می‌شود (`ai_conn:<userId>`)
- پس از اتصال، همه قابلیت‌ها (چت، دیباگ، عکس، فایل، ZIP، ایجنت گیت‌هاب) با مدل خود کاربر کار می‌کنند
- حذف اتصال: `/logout`، `/ai off` یا دکمه «🗑 حذف اتصال»
- تست محلی: `node test.mjs`

## فضای کار و حافظهٔ جداگانه برای پروژه‌ها

قابلیت پروژه‌ای به‌صورت افزایشی اضافه شده است. تا وقتی پروژه‌ای را فعال نکنید، ربات از همان حافظه و فضای کاری پیش‌فرض قبلی استفاده می‌کند. برای ساخت و مدیریت پروژه‌ها:

```text
/project                     راهنمای فرمان‌ها و پروژهٔ فعال
/project new <نام>           ساخت پروژه و فعال‌کردن آن
/project list                فهرست پروژه‌ها
/project use <نام>           جابه‌جایی به یک پروژه
/project off                 بازگشت به حافظه و فضای کار پیش‌فرض
/project delete <نام>        پیش‌نمایش و تأیید حذف پروژه، حافظه و فایل‌های workspace آن
/project repo <owner/repo>   اتصال مخزن GitHub به پروژهٔ فعال
/project sync                منوی دریافت/ارسال GitHub
/project pull [overwrite]    دریافت فایل‌ها؛ overwrite پس از تأیید تعارض‌ها
/project push                پیش‌نمایش و ارسال پس از تأیید
```

منوی `/project` امکان انتخاب پروژه و اتصال GitHub را از طریق دکمه‌های شیشه‌ای هم می‌دهد. ابتدا با `/github <توکن>` توکن را وصل کنید، سپس پروژه را فعال و مخزن را با `/project repo owner/repo [branch]` ثبت کنید. `pull` فایل‌های جدید را بدون overwrite وارد workspace می‌کند؛ فایل‌های هم‌نام حفظ می‌شوند. `/project pull overwrite` پیش‌نمایش فایل‌های متعارض را نشان می‌دهد و فقط پس از تأیید آن‌ها را جایگزین می‌کند. `push` مقصد و فهرست فایل‌ها را پیش‌نمایش می‌دهد و فقط با تأیید یک‌بارمصرف، فایل‌های workspace را به‌صورت commit اضافه/به‌روزرسانی می‌کند؛ فایل‌های دیگر مخزن حذف نمی‌شوند. فایل‌های `.env` و مسیرهای حساس/ساخت خروجی از sync کنار گذاشته می‌شوند و دریافت محدودیت اندازه و تعداد دارد. هر پروژه حافظه و workspace خودش را دارد؛ داده‌های قدیمی پیش‌فرض حفظ می‌شوند و با `/project off` در دسترس‌اند.

## تأیید عملیات تغییردهنده

ابزارهای Agent که فایل workspace یا حساب GitHub را تغییر می‌دهند، پیش از اجرا یک preview و دکمهٔ «تأیید و اجرا» می‌فرستند. تأیید فقط برای همان کاربر، همان گفتگو و همان payload معتبر است، پنج دقیقه اعتبار دارد و یک‌بار مصرف است؛ لغو یا انقضا هیچ تغییری اعمال نمی‌کند. همین سازوکار برای `/workspace_clear`، `/project delete` و overwrite فایل‌های pullشده نیز استفاده می‌شود. پیش از اجرا، پروژهٔ فعال، مقصد GitHub و fingerprint فایل‌ها/توکن دوباره بررسی می‌شود؛ اگر عوض شده باشند، باید preview تازه گرفت.

## اتصال امن Cloudflare

در **گفت‌وگوی خصوصی** با ربات `/cloudflare` را بزنید. ربات یک لینک HTTPS موقت می‌دهد؛ API Token را فقط در فرم مرورگر وارد کنید، نه در تلگرام. پس از اعتبارسنجی، به تلگرام برگردید و اتصال را صریحاً تأیید کنید. لینک ۱۰ دقیقه اعتبار دارد و یک‌بار مصرف است؛ توکن با AES-GCM در D1 ذخیره می‌شود و فقط با کلید جداگانهٔ Worker قابل رمزگشایی است. قطع اتصال: `/cloudflare off`.

برای فعال‌کردن ذخیرهٔ رمزگذاری‌شده، یک بار کلید ۳۲ بایتی Base64 بسازید و آن را فقط به‌عنوان Worker Secret تنظیم کنید:

```bash
openssl rand -base64 32
npx wrangler secret put CLOUDFLARE_ENCRYPTION_KEY
```

اگر از داشبورد Cloudflare استفاده می‌کنید، خروجی دستور اول را به‌عنوان مقدار Secret وارد کنید. کلید را در Telegram، GitHub، `wrangler.toml` یا logها قرار ندهید. تغییر کلید باعث می‌شود tokenهای قبلی قابل رمزگشایی نباشند؛ در آن صورت کاربر باید Cloudflare را دوباره وصل کند.

دسترسی‌های پیشنهادی را برحسب نیاز محدود کنید: `Zone: Zone Read` برای فهرست Zoneها، `DNS: DNS Read` برای دیدن رکوردها، `DNS: DNS Write` برای ساخت/ویرایش/حذف رکورد، و `Workers Scripts Read` برای فهرست Workerها. دسترسی را به منابع موردنیاز محدود کنید. تغییر DNS قبل از اجرا مقدار فعلی/جدید را نمایش می‌دهد و به تأیید یک‌بارمصرف نیاز دارد. نسخهٔ اول فقط metadata و تنظیمات مشاهده‌پذیری Worker را می‌خواند و سورس، secretها، deploy یا حذف Worker را تغییر نمی‌دهد. برای مشاهدهٔ Workerها، `account_id` را از داشبورد Cloudflare به ربات بدهید.

## تنظیمات لازم

### Secrets (از طریق Cloudflare Dashboard یا Wrangler CLI)

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put OPENAI_API_KEY        # اختیاری
npx wrangler secret put ADMIN_SECRET           # اختیاری - برای پنل ادمین
npx wrangler secret put WEBHOOK_SECRET         # اختیاری
npx wrangler secret put CLOUDFLARE_ENCRYPTION_KEY # اختیاری؛ فقط برای اتصال Cloudflare
npx wrangler secret put CREDENTIALS_ENCRYPTION_KEY # برای رمزگذاری credentialهای GitHub
```

⚠️ `TELEGRAM_BOT_TOKEN` را در تنظیمات Worker با نوع **Secret** ذخیره کنید، نه به‌صورت متغیر plain text. برای GitHub Actions، فقط `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID` را در Secrets مخزن قرار دهید؛ توکن تلگرام در Secret خود Worker باقی می‌ماند. Wrangler با deploy معمولی Secretهای موجود را حذف نمی‌کند.

### Bindings

- **D1 Database**: برای حافظه گفتگو و کاربران
- **KV Namespaces**: 
- `STATS`: آمار، تنظیمات، workspace و پروژه‌ها؛ توکن‌های قدیمی GitHub فقط تا زمان مهاجرت lazy
- `DB`: تاریخچه، approvalها، و credentialهای GitHub/Cloudflare به‌صورت AES-GCM encrypted
  - `FILES`: متادیتای فایل‌ها

## امنیت

- توکن‌های جدید GitHub با AES-GCM و AAD وابسته به کاربر در D1 ذخیره می‌شوند؛ برای فعال‌بودن این قابلیت `CREDENTIALS_ENCRYPTION_KEY` را به‌عنوان Worker Secret تنظیم کنید (اگر موجود باشد، `CLOUDFLARE_ENCRYPTION_KEY` نیز برای سازگاری قابل استفاده است)
- توکن‌های قدیمی plaintext در KV هنگام استفاده، در صورت موجودبودن کلید رمزگذاری به‌صورت lazy به D1 منتقل و از KV حذف می‌شوند؛ تا قبل از آماده‌شدن کلید، توکن قدیمی برای حفظ سازگاری قابل استفاده می‌ماند، اما توکن جدید بدون کلید هرگز ذخیره نمی‌شود
- credential GitHub حداکثر ۳۰ روز اعتبار ذخیره‌سازی دارد؛ حذف اتصال یک tombstone در D1 نگه می‌دارد تا مهاجرت هم‌زمان نتواند credential حذف‌شده را برگرداند
- توکن Cloudflare از چت تلگرام دریافت نمی‌شود؛ از فرم HTTPS یک‌بارمصرف می‌آید و پیش از ذخیره در D1 با AES-GCM رمز می‌شود
- فایل‌های `.env` و رمزها در ZIP نادیده گرفته می‌شوند
- پیام حاوی توکن بلافاصله از چت پاک می‌شود
- تأیید عملیات در D1 به کاربر و گفتگو bind می‌شود؛ payload موقت فقط تا پنج دقیقه در KV نگه داشته می‌شود و تأیید تکراری پذیرفته نیست
- خطاهای خام provider/runtime و stack trace به کاربر نمایش داده نمی‌شوند؛ لایهٔ مرکزی پیام‌های کوتاه بر اساس سرویس/وضعیت می‌سازد و لاگ‌های برنامه فقط context، نوع خطا و در صورت وجود status را ثبت می‌کنند
- خطاهای پیش‌بینی‌نشده در HTTP با پاسخ عمومی و `request_id` پاسخ داده می‌شوند؛ برای تشخیص مشکل، شناسهٔ درخواست را نگه دارید و جزئیات داخلی را در چت یا مرورگر منتشر نکنید
